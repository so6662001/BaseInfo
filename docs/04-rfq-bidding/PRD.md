# 方案四：安全版询价竞价 - PRD

> 版本：v1.0  
> 产品定位：钢贸大客户招标式采购平台

---

## 1. 业务概述

### 1.1 业务背景

- 钢贸大客户（中铁/中建/制造业/工程）单笔采购 500-50000 吨，年采购数千万至数亿
- 大客户传统采购：业务员上门 + 多家询价 + 内部比价 → 流程长、效率低
- 商家面对大客户询价：付出报价成本但中标率不可控
- 询价过程中商家担心客户被同行撬走

### 1.2 产品定位

**货袋子招标平台**：钢贸行业 B2B **资质认证大客户**与 **认证商家**的高效撮合通道。

### 1.3 4 大设计铁律

```
铁律 1：只对大客户开放（不卷散单）
铁律 2：报价单向透明（买家看得到，商家互盲）
铁律 3：综合评分（不只是价格）
铁律 4：老客户保护（防止撬单）
```

### 1.4 业务边界

| 范围内 | 范围外 |
|--------|--------|
| 资质认证大客户询价 | 普通买家询价（走库存池） |
| 单笔 ≥ 500 吨 / 年采购 ≥ 5000 吨 | 散单 |
| 标准化钢材 | 非标定制（暂不） |
| 平台撮合 + 担保结算 | 询价方私下交易 |

### M3 - 商家匹配（推送策略）

#### M3.1 匹配算法

```
当询价单发布，系统自动执行：

第一步：候选筛选
  • 商家有该 SKU 的发货能力（或近 30 天内有过该 SKU 销售）
  • 商家信用 ≥ AA
  • 商家月活 ≥ 30 天
  • 商家在采购方接受的供应商范围内（如有白名单）
  • 商家不在采购方的"屏蔽列表"内
  • 商家产能足够（基于历史交易数据）

第二步：评分排序
  匹配分 = 
      SKU 契合度 × 30%      // 完全匹配/部分匹配
    + 物流距离 × 20%        // 近 = 高分
    + 信用等级 × 20%        // AA以上 = 高分
    + 历史价格竞争力 × 15%   // 历史报价是否有竞争力
    + 平台活跃度 × 15%       // 月活 = 高分

第三步：分级推送
  Top 10  → APP Push + 短信 + 电话（重要询价）
  Top 11-30 → APP Push + 站内信
  Top 31-50 → 工作台首页弹窗
  Top 51+ → 不推送（避免打扰）
```

#### M3.2 老供应商优先权

- 老供应商**强制推送**（不参与匹配排序）
- 老供应商额外通知方式：电话邀请

### M5 - 多维评分

#### M5.1 评分模型

```python
# 综合评分算法

竞价综合分 = 
    价格分 × 价格权重
  + 交期分 × 交期权重
  + 信用分 × 信用权重
  + 服务分 × 服务权重

【价格分】（基础）
价格分 = (最高报价 - 该商家报价) / (最高报价 - 最低报价) × 100

【交期分】
交期分 = MAX(0, 100 - (实际交期 - 要求交期) × 20)

【信用分】
信用分 = 商家信用分 / 10  // 直接折算

【服务分】
服务分 = 历史好评率 × 50 + 历史按时交付率 × 50

【加分项】（独立加在综合分上）
+ 老供应商保护：5-10 分
+ 增值服务承诺：1-3 分（免费物流、急速发货等）
+ 平台活跃度：0-3 分
```

#### M5.2 排名机制

- 商家在**报价页面**只能看到自己的排名（如 "3 / 8 家"），不能看到具体分数和别人报价
- 商家可看到**自己与第一名的差距**（"您与第一名差距 3 分"）
- 平台向买家展示**所有报价**（分数 + 报价 + 商家信息）
- **截止后**，商家可看到完整排名（不含具体报价）

#### M5.3 中标判断

```
模式 1：综合分最高者中标（默认）
模式 2：综合分前 3 名进入下一轮
模式 3：人工评标（买家从前 3 名中选择）
模式 4：分单中标（每个 SKU 选不同商家）
```

### M7 - 老客户保护

#### M7.1 三层保护

##### 第一层：老供应商优先权

- 该买家与某商家**累计交易**（含线下/平台）：
  - ≥ ¥100 万：自动加 5 分
  - ≥ ¥500 万：自动加 8 分
  - ≥ ¥1000 万：自动加 10 分

- 老供应商可获 **"最后还价权"**：看到中标价后，老供应商有 24h 时间机会以等价或低 1% 价格匹配中标。

##### 第二层：客户归属保护

- 商家可在自己的"客户管理"中**主动加白**
  - 自己的核心客户（VIP 客户）
  - 加白的客户**不会显示在其他商家的询价池中**
- 加白上限：每商家可加白 50 家（防止滥用）
- 加白需举证：上传过去 12 个月的交易记录

##### 第三层：限制询价频次

- 同一买家同一规格 30 天内**最多 1 次询价**
  - 防止买家用平台反复压价老供应商
- 同一买家同一规格历史最低成交价的 -5% 以下报价 → 平台拦截

## 4. 风控机制

### 4.1 钓鱼询价监控

| 异常 | 检测 | 处置 |
|------|------|------|
| 频繁发布无意向询价 | 成交率 < 30% | 降级 + 限流 |
| 发布后频繁撤销 | 撤销率 > 30% | 警告 + 保证金扣除 |
| 报价后不签合同 | 中标后不履约率 > 20% | 限制资格 |

### 4.2 围标串通监控

| 异常 | 检测 | 处置 |
|------|------|------|
| 多账户报价相似 | IP / 设备 / 行为聚类 | 取消资格 + 封号 |
| 报价高度集中 | 中位数偏离度 < 0.5% | 人工核查 |
| 关联企业报价 | 工商图谱关联 | 屏蔽 |

### 4.3 价格保护

| 机制 | 说明 |
|------|------|
| 成本警戒线 | 平台维护，低于自动屏蔽 |
| 历史最低保护 | 该规格历史最低成交价 -5% 以下拦截 |
| 异常低价审核 | 偏离市场价 -15% 触发人工审核 |

## 5. 业务流程

### 5.1 主流程：买家发布询价 → 中标

```
买家登录 → 创建询价单（结构化录入）
        ↓
平台审核（≤ 4 小时）
        ↓
推送给匹配商家（10-50 家）
        ↓
商家收到 → 报价（3 天内）
        ↓
平台综合评分 → 排序
        ↓
评标日 → 公布中标
        ↓
中标商家 24h 内确认
        ↓
进入订单流程（合同/支付/发货/签收/开票）
        ↓
履约完成 → 双向评价
```

### 5.2 主流程：商家收到询价 → 报价

```
商家收到推送（APP + 短信）
        ↓
查看询价详情 → 评估能力
        ↓
进入报价页面：
  • 输入报价（每个 SKU）
  • 输入交期
  • 选择加分项
  • 写报价说明
        ↓
保存草稿 / 提交
        ↓
查看自己排名（不能看别人）
        ↓
（可选）调整报价 1 次
        ↓
等待评标
        ↓
中标 → 确认 → 履约
非中标 → 收到失利分析
```

## 6. 非功能需求

### 6.1 性能

- 询价单创建 ≤ 5 秒
- 商家匹配推送 ≤ 30 秒
- 报价提交 ≤ 2 秒
- 评标算法 ≤ 10 秒（即使 100+ 报价）
- 中标公告推送延迟 ≤ 30 秒

### 6.2 数据保密

- 商家报价保密（不互相可见）
- 买家信息保护（防止商家私下绕开平台）
- 核心数据加密存储 + 传输

### 6.3 公平性

- 评分算法公开透明
- 中标结果可申诉
- 平台不偏袒任何一方
