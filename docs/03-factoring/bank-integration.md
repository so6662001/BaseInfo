# 方案三：应收账款保理 - 银行/保理对接路径

> 这是金融业务能否落地的关键。资金方对接需要平台、法务、商务、技术联动。

---

## 1. 三阶段合作模式演进

```
【阶段一】导流模式（0-6 个月）
   平台 → 推荐客户 → 银行 → 银行风控 → 银行放款
   
   平台收：导流佣金 1-2%（一次性）
   风险：银行承担
   优势：上线最快、风险最低
   局限：收入低、不沉淀客户

      ↓

【阶段二】助贷/联合贷款（6-24 个月）
   平台 → 提供数据风控 → 银行 → 联合审批 → 银行放款
   
   平台收：服务费 + 利息分成 10-50%
   风险：少量分担（保证金 5-10%）
   优势：商业模式好
   局限：需通过监管认证

      ↓

【阶段三】自营保理（24 个月+）
   平台收购/控股商业保理公司 → 自有资金 + ABS → 自主放款
   
   平台收：全部利差
   风险：自担
   优势：利润最大化
   局限：资金消耗大、合规要求高
```

## 2. 优先合作伙伴清单

### 2.1 互联网银行（P0 - 最快上线）

| 银行 | 优势 | 接洽路径 |
|------|------|---------|
| **网商银行** | 数据驱动、流程快、API 成熟 | 阿里产业互联网部门 |
| **新网银行** | 灵活、对供应链金融友好 | 直接对接业务部 |
| **众邦银行** | 对中小企业敞开 | 直接对接 |
| **微众银行** | 微粒贷 / 微业贷 | 腾讯生态合作 |

**优势**：审批快、API 成熟、流程线上化、利率合理（年化 9-12%）。

**对接周期**：业务沟通 1-2 月，技术对接 1-2 月。

### 2.2 国有大行供应链金融部（P1 - 资金量大）

| 银行 | 产品 | 优势 |
|------|------|------|
| **建行供应链金融** | "云税贷"、"云收快贷" | 数据 + 规模 |
| **工行供应链金融** | "数链贷" | 资金便宜 |
| **中行电子保函** | "中银 e 业达" | 国企背景 |
| **农行 e 链贷** | 重点扶持产业链 | 政策支持 |

**优势**：资金量大、利率最低（年化 5-7%）、信誉背书。

**局限**：流程相对慢、要求高。

### 2.3 股份制银行供应链金融（P2 - 灵活创新）

- **平安银行**：橙 e 网（钢铁、塑料、煤炭等大宗品）
- **招商银行**：易企赢、订单贷
- **兴业银行**：金芝麻
- **民生银行**：易商贷

### 2.4 商业保理公司（P3 - 灵活补充）

| 类型 | 代表 | 特点 |
|------|------|------|
| 头部保理 | 中企云链、易见股份、深圳怡亚通 | 经验丰富、模式成熟 |
| 区域保理 | 上海/深圳保理 | 本地化、灵活 |
| 央企保理 | 中铁、中建商业保理 | 资金充裕、信誉好 |

### 2.5 金融科技服务商

- **联易融**（科技服务+ABS）
- **金蝶征信**（数据风控）
- **同盾科技**（反欺诈）

## 5. 关键合规要点

### 5.1 资金方资质核验

| 资金方 | 必备资质 |
|--------|---------|
| 银行 | 银行业金融许可证 |
| 商业保理 | 商业保理资质（地方金融监管局批准） |
| 网络小贷 | 网络小贷牌照 |
| 信托 | 信托业务资质 |

### 5.2 协议关键条款

- **资金来源声明**：资金方明确资金来源合规
- **风险隔离**：资金方对放款风险负责（导流/助贷分清）
- **数据使用**：明确数据范围、用途、保密
- **客户保护**：明确禁止暴力催收、禁止砍头息
- **退出机制**：合作终止后客户/数据处理
- **监管配合**：双方配合监管检查

### 5.3 用户协议关键条款

- **借款合同**：金额、利率、期限、还款方式
- **担保合同**：法人个人连带责任
- **数据授权**：明确平台获取/使用范围
- **征信查询授权**：人行征信
- **风险提示**：以鲜明字体显示

## 6. 银企直连技术方案

### 6.1 直连模式

```
平台 ─── HTTPS API ─── 银行直连接口
                         ├── 银行账户开户
                         ├── 余额查询
                         ├── 转账支付
                         ├── 流水查询
                         └── 对账文件
```

### 6.2 银行常见 API

| 接口 | 用途 |
|------|------|
| 账户开立 | 为商家开立银行账户 |
| 实名认证 | 三/四要素认证 |
| 账户查询 | 余额、流水 |
| 单笔代付 | 平台向商家付款 |
| 批量代付 | 批量结算 |
| 单笔代收 | 还款扣款 |
| 协议代扣 | 自动还款 |
| 对账文件 | 每日对账 |

### 6.3 安全规范

- 所有 API 走 **HTTPS + 双向证书**
- 报文体 **AES 加密 + RSA 签名**
- 密钥定期轮换
- 关键操作 **二次确认**
- IP 白名单 + 频次限制

## 7. 资产证券化（ABS）路径

### 7.1 ABS 模式（成熟期）

```
平台积累优质应收资产
    ↓
打包成资产池（同质性、可预测）
    ↓
设立 SPV（特殊目的实体）
    ↓
评级机构评级
    ↓
券商承销
    ↓
公开发行（交易所/银行间）
    ↓
募集资金回归平台再投放
```

### 7.2 适用条件

- 累计放款 ≥ ¥30 亿
- 90 天逾期率 < 1.5%
- 存量优质资产 ≥ ¥5 亿
- 评级 ≥ AA-
- 完善的资产管理 + 服务能力

### 7.3 收益模型

```
ABS 发行规模 ¥10 亿
ABS 票面利率 5%
基础资产收益 9%
利差 4%

平台分成（扣除费用）≈ 2-3%
年化收益 = ¥10亿 × 2.5% = ¥2500 万
```
