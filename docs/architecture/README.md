## 二、技术栈选型

| 层 | 选型 | 理由 |

| 微服务框架 | **Spring Cloud Alibaba 2023.x** | 国内生态成熟、Nacos/Sentinel/Seata 完整 |

## 四、核心数据库设计原则

### 4.1 分库策略

| 库 | 服务 | 分库策略 |
|----|------|---------|
| db_user | user-service | 主从 |
| db_credit | credit-service | 主从 + ES |
| db_inventory | inventory-service | 主从 + ES |
| db_finance | finance-service | 主从 + 异地容灾 |
| db_rfq | rfq-service | 主从 |
| db_mcm | mcm-service | 主从 + Doris |
| db_order | order-service | **按 user_id 分 16 库** |
| db_log | 日志库 | **按月分表** |

### 4.2 读写分离

- 所有业务服务采用 **1 主 N 从** 架构
- 读流量自动路由到从库
- 通过 ShardingSphere ReadwriteSplitting 实现

### 4.3 缓存策略

| 数据 | 缓存层 | TTL |
|------|--------|-----|
| 字典数据 | 本地 + Redis | 1d |
| 用户信息 | Redis | 1h |
| 商品信息 | Redis | 1h |
| 信用报告 | Redis | 24h |
| 价格指数 | Redis | 5min |
| 排行榜 | Redis ZSet | 实时 |

## 五、关键技术方案

### 5.1 订单状态机（统一实现）

```
所有方案的"订单"统一由 order-service 管理：

CREATED → PAID → SHIPPING → IN_TRANSIT → SIGNED → CONFIRMED → INVOICED → COMPLETED
   ↓        ↓       ↓
CANCELLED REFUND DISPUTE
```

使用 **Spring StateMachine** 实现，统一事件驱动。

### 5.2 分布式事务

- **保理放款**：使用 Seata TCC
- **订单 + 支付**：使用 Seata AT
- **库存扣减**：Redis Lua 原子操作 + 最终一致

### 5.3 异步解耦

| 场景 | MQ Topic | 说明 |
|------|---------|------|
| 订单创建 | order.created | 触发库存锁定、合同生成 |
| 订单支付 | order.paid | 触发发货通知、放款 |
| 信用变化 | credit.changed | 触发预警推送、重新评估 |
| 库存发布 | inventory.published | 触发智能撮合 |
| 营销触达 | marketing.send | 异步发送短信/邮件 |

### 5.4 权限模型

- RBAC + ABAC 混合
- 三层：用户 → 角色 → 权限
- 数据权限：按商家、按地区、按层级

### 5.5 限流降级

| 接口 | 策略 |
|------|------|
| 信用查询 API | 用户级 QPS 100，IP 级 QPS 1000 |
| 库存搜索 | 用户级 QPS 50 |
| 支付/放款 | 不限流，但有熔断 |
| 后台 API | 内部限流较松 |

## 七、安全方案

### 7.1 网络安全

- DDoS 防护（云厂商）
- WAF Web 应用防火墙
- HTTPS 全站
- VPC 内网隔离

### 7.2 数据安全

- 数据库加密（透明数据加密 TDE）
- 敏感字段加密（AES-256）
- 数据脱敏（手机号、身份证）
- 备份加密 + 异地备份

### 7.3 应用安全

- OAuth 2.0 + JWT
- API 签名 + 时间戳防重放
- SQL 注入防护（MyBatis 参数化）
- XSS / CSRF 防护
- 接口幂等

### 7.4 业务安全

- 反欺诈引擎
- 设备指纹
- 行为风控
- 验证码防爬虫
