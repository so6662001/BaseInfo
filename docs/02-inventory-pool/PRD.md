# 方案二：滞销库存共享池 - PRD

> 版本：v1.0  
> 产品定位：钢贸商家间 B2B 现货置换撮合平台

---

## 1. 业务概述

### 1.1 业务背景

- 钢贸商家平均库存 5000-50000 吨，资金占用 1500 万-1.5 亿
- 行业平均周转天数 30-60 天，滞销品（90 天+）占 10-30%
- 单家商家解决滞销主要靠"打折出货"或"压价给同行"
- 信息严重不对称：A 商家压在仓库的货，B 商家正在到处找

### 1.2 产品定位

**货袋子库存通**：仅向**平台认证商家**开放的 B2B 现货置换平台。商家之间互通有无，平台提供撮合、担保、物流、结算、开票全链路服务。

### 1.3 核心用户

| 角色 | 说明 |
|------|------|
| 发布方（卖家） | 有滞销/富余库存的商家 |
| 需求方（买家） | 需要紧急补货的商家 |
| 平台 | 撮合、担保、物流、结算 |

### 1.4 关键边界

| 项 | 规则 |
|----|------|
| 谁能发布 | 仅平台认证商家（信用 ≥ A） |
| 谁能购买 | 仅平台认证商家（B2B，不对终端） |
| 货物物权 | 归发布方，平台不持有 |
| 资金 | 平台担保账户中转 |
| 发票 | 发布方开给购买方 |
| 物流 | 发布方负责（推荐用平台网络货运） |
| 平台收益 | 撮合费 1%（买方付） + 物流毛利 + 仓储 |

### M2 - 智能撮合

#### M2.1 撮合算法

```
当商家 A 发布库存 X，系统自动执行撮合：

第一步：候选筛选
  • 规格完全匹配（必须）
  • 数量满足（需求量 ≤ 库存量）
  • 仓库距离 < 500km
  • 价格在合理区间（市场价 ±15%）
  • 买家信用 ≥ A

第二步：评分排序
  匹配分 = 
      规格契合度 × 30%
    + 距离分（300km 内满分）× 25%
    + 历史购买偏好 × 20%
    + 信用等级 × 15%
    + 活跃度（最近30天登录）× 10%

第三步：分级推送
  Top 5：APP Push + 短信（实时）
  Top 6-20：APP Push（实时）
  Top 21-50：工作台首页弹窗
  Top 51+：每日邮件汇总
```

#### M2.2 个性化推荐

- 基于商家 ERP 历史采购数据
- 基于浏览行为（看了又看）
- 基于关注列表（关注的库存类型）
- 基于地理位置（本地优先）

### M5 - 担保交易

#### M5.1 下单流程

```
买家选择库存 → 点击"立即购买"
   ↓
确认订单（数量、价格、账期、收货地址、开票信息）
   ↓
在线支付 → 平台担保账户
   ↓
通知卖家发货（24h 内）
   ↓
卖家通过平台网络货运/自有车队发货
   ↓
物流跟踪 → 买家签收 + 验货（48h 内）
   ↓
确认收货 → 平台放款给卖家
   ↓
卖家 7 天内开票 → 票流闭环
```

#### M5.2 支付方式

| 方式 | 适用 | 时效 |
|------|------|------|
| 银企直连 | 大额（≥ 50 万） | T+0 |
| 网银支付 | 中小额 | T+0 |
| 银承汇票 | 协议账期 | T+0 |
| 平台余额 | 充值/退款 | 实时 |

#### M5.3 担保账户机制

- 买家付款 → 平台 **专用担保账户**（与平台运营账户隔离）
- 卖家发货 + 买家收货确认 → **自动放款**
- 争议产生 → **冻结资金**直到争议解决
- 账户每日对账 + 异地备份

#### M5.4 平台费用

```
基础撮合费：成交额 × 1%（买方付，下单时一并支付）
担保费：免费（含在撮合费里）
开票费：免费
物流费：按网络货运实际成本，平台抽 5-10%
仓储费：可选，3-5 元/吨/月
增值服务：质检、加工、保险等，按需另付
```

### M7 - 自动开票

#### M7.1 开票流程

```
买家收货确认 → 触发开票（可设置发货时即开）
   ↓
平台调用开票 API（航信百望）
   ↓
卖家税控盘 → 开票 → 推送电子发票
   ↓
买家收到：APP 通知 + 邮件 + 票据归档
   ↓
四流闭环（合同+货物+资金+发票）
```

#### M7.2 开票要素

- 发票类型：增值税专票 13% / 普票 / 小规模 1%/3%
- 抬头：买家公司名称
- 税号：买家统一社会信用代码
- 商品名称：标准 SKU 名称（与下单一致）
- 数量、单价、金额、税额
- 备注：订单号

#### M7.3 票流校验（与四流合一联动）

```
平台自动校验：
  合同金额 = 支付金额 = 开票金额 ✓
  合同品名 = 物流品名 = 开票品名 ✓
  合同数量 = 物流数量 = 开票数量 ✓
  合同主体 = 收款主体 = 开票主体 ✓
  
任一不一致 → 拦截开票 + 人工合规审核
```

## 4. 标准 SKU 体系（核心支撑）

```

   ↓        ↓       ↓        ↓        ↓        ↓        ↓         ↓
```

```
SKU 编码：[品类2位][材质4位][规格6位][钢厂3位] = 15 位
示例：LWHRB400E0200012SHA

L  - 螺纹钢（L=Luowen）
W  - 圆钢（W=Wire）
H  - 工字钢（H=H型）
...
```

- 库存匹配准确率提升至 99%
- 撮合成功率提升 50%
- 价格指数计算可靠
- 跨商家库存可量化对比

### 5.2 主流程：购买库存

```
买家浏览 / 搜索库存
        ↓
查看详情 → 询价（可选） / 直接下单
        ↓
确认订单（数量、收货地址、开票信息）
        ↓
在线支付 → 平台担保账户
        ↓
卖家 24h 内发货
        ↓
平台网络货运（推荐）/ 自提
        ↓
物流跟踪
        ↓
签收 + 验货（48h 内）
        ↓
确认收货 → 平台放款 → 卖家开票
```

## 6. 防作弊机制

| 作弊行为 | 防范措施 |
|---------|---------|
| 虚假库存（钓鱼引流） | 强制磅单 + 仓库视频核验 + 人工抽检 |
| 价格操纵（同伙刷量） | 风控识别（IP、设备、关联账号） |
| 跳单（私下交易） | 沟通必须站内 + 屏蔽联系方式 |
| 以次充好 | 验货争议 + 信用扣分 |
| 频繁取消 | 取消率 > 20% 降权或封禁 |
| 恶意中标不付款 | 买家保证金机制 |
