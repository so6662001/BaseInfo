## 二、5 大方案的协同关系

5 个方案不是孤立的功能，它们之间存在强协同：

```
                    ┌────────────────────────┐
                    │  方案一：信用查询黑名单  │
                    │ （平台数据基础设施）     │
                    └───────────┬────────────┘
                                │
              ┌─────────────────┼─────────────────┐
              │                 │                 │
              ▼                 ▼                 ▼
    ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
    │方案二：滞销   │  │方案三：保理   │  │方案四：竞价   │
    │库存共享池    │  │ 金融服务     │  │ 大客户订单   │
    └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
           │                 │                 │
           └─────────────────┼─────────────────┘
                             ▼
                ┌────────────────────────┐
                │ 方案五：商家分层激活    │
                │ （运营触达底盘）        │
                └────────────────────────┘
```

- **方案一** 沉淀的信用数据 → 喂给 **方案三** 做风控
- **方案二** 启动的 B2B 撮合 → 拉来 **方案四** 的大客户
- **方案五** 找到的 A/B 层商家 → 优先享受方案 1/2/3/4 的服务
- **方案三** 的金融能力 → 反过来推动商家更深度使用方案 1/2

## 六、关键设计原则（贯穿全文档）

### 6.1 商业原则

1. **不与商家抢生意** —— 平台是商家的武器，不是商家的对手
2. **数据资产化** —— 2000 家 ERP 是金矿，每个功能都要利用并强化数据壁垒
3. **单点突破** —— 不追求全国铺开，区域密度优先
4. **病毒传播设计** —— 每个核心功能都要有让商家"自发推荐"的钩子

### 6.2 产品原则

1. **MVP 优先** —— 先用最小功能跑通闭环，再迭代
2. **B 端体验** —— 钢贸老板不是互联网原住民，操作要"傻瓜化"
3. **PC + APP 双端** —— PC 主操作 + APP 主提醒
4. **强 ERP 集成** —— 平台必须深度嵌入商家的日常 ERP 工作流

### 6.3 技术原则

1. **微服务化** —— 5 个方案独立服务，互不耦合
2. **数据中台先行** —— 信用数据、商家数据、交易数据统一治理
3. **接口优先** —— 所有功能先有 API，再有页面，方便后续生态化
4. **灰度发布** —— 任何新功能先在 A 层试点，再扩 B/C/D
