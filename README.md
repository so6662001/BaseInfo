# 钢铁行情指数算法

基于商家**挂牌价 + 库存**数据编制钢材行情指数，产出两类指数：

| 指数 | 含义 | 输出 |
| --- | --- | --- |
| 钢铁综合行情指数 | 不分品类的全市场行情 | `out.composite` |
| 分品种行情指数 | 螺纹钢、热轧、冷轧、中厚板、型钢…… 各自的行情 | `out.variety` |

两者共用同一套底层环比，自上而下可分解：综合指数的日涨跌恰好等于各品种日涨跌的加权平均，
所以"今天综合指数涨了 0.3%，其中螺纹贡献 0.12 个百分点"这类归因可以直接给出，不会出现口径打架。

算法的重点不在指数公式，而在**如何在一堆有人捣乱的数据里算出可信的指数**。
商家挂牌数据里真实存在的问题：单位填成元/公斤、价格手滑多打一位、同一条资源刷几百遍、
挂着半年不改价充数、长期报低价 25% 抢排名、注册一堆小号同步报价刷话语权。
这些数据如果原样进指数，指数就是垃圾。本算法用五层清洗 + 商家可信度评分 + 权重封顶来处理它们，
并且每一条被剔除的记录都可回溯、可申诉复核。

```bash

# 计算真实数据
python -m steel_index run --listings 挂牌价.csv --inventory 库存.csv --outdir out
```

代码调用：

```python
from steel_index import run_index

out = run_index(listings_df, inventory_df)      # 库存表可选
```

## 输入数据

挂牌价明细，一行一条报价。列名支持中英文别名自动识别（`日期/报价日期/dt`、`挂牌价/报价/单价`……）：

| 列 | 必需 | 说明 |
| --- | --- | --- |
| 日期 | 是 | 报价日期 |
| 商家id | 是 | 商家唯一标识 |
| 品种 | 是 | 自由文本，如"螺纹钢"/"热卷"/"HRB400E"，自动归一到标准品种 |
| 挂牌价 | 是 | 数值，配合"单位"列自动折算为元/吨 |
| 规格 | 建议 | 自由文本，如"Φ20"/"5.75mm"/"200*200"，自动提取尺寸并分档 |
| 城市 | 建议 | 用于划分价格单元，缺失则退化为全国口径 |
| 库存量 | 建议 | 权重来源。缺失时按同单元中位数的一半保守填充 |
| 钢厂、材质、单位 | 可选 | 钢厂参与 SKU 识别；单位用于量纲折算 |

库存也可以单独一张表传入，会按双方共有的维度（日期/商家/品种/规格档/城市）自动连接。

## 输出

`composite`（综合指数）与 `variety`（分品种指数）的主要列：

| 列 | 说明 |
| --- | --- |
| `index_value` | 指数值，基期 = 100 |
| `index_smooth` | EWMA 平滑指数 |
| `chg_1d / chg_5d / chg_22d / chg_250d` | 日/周/月/年涨跌幅 |
| `price_level` | 加权均价（元/吨） |
| `n_matched / n_merchants / n_cells` | 当期匹配样本数、商家数、价格单元数 |
| `n_up / n_down / n_flat / diffusion` | 涨跌广度：指数告诉你市场往哪走，广度告诉你是普涨还是被少数样本拉起来的 |
| `low_confidence` | 样本不足或插补占比过高的标记，发布前应人工复核 |

配套产出：

- `cells` —— 单元级（品种×规格档×城市）明细，含环比、价格水平、样本质量
- `contribution` —— 各品种对综合指数涨跌的贡献度分解
- `cleaning.rejected` —— 被剔除的每一条记录，带规则编号与人可读原因
- `credibility.scores` —— 商家可信度评分与各项行为指标
- `diagnostics` —— 逐日样本质量：剔除率、有效样本量、头部商家权重占比、插补占比

## 清洗规则

分层执行，每层只在上一层的存活样本上工作，保证统计量本身不被垃圾数据污染。

| 层 | 规则 | 处理 |
| --- | --- | --- |
| L0 结构 | R001 商家标识为空 / R002 日期非法或未来日期 / R003 价格非数值 / R004 品种无法识别 | 剔除 |
| L1 量纲 | R010 价格非正 / R012 超出品种物理边界 | 剔除 |
| | F011 按计价单位折算 / F012 量纲自动修复（元/公斤误填为元/吨） | **修复保留** |
| | R013 库存为负 / R014 库存超单 SKU 上限 | 库存作废，价格保留 |
| L2 去重 | R022 单商家单日报价条数异常（机器灌水） | 整日剔除 |
| | R020 完全重复 / R021 同商家同日同 SKU 重复挂牌 | 保留最贴近组内中位数的一条 |
| L3 横截面 | R030 同品种同规格档同城市内 MAD 稳健 Z 超阈值 / R031 大样本单元分位截尾 | 剔除 |
| L4 纵向 | R040 单日涨跌超品种上限 / R041 孤立毛刺（涨完立刻回落） | 剔除 |
| | F042 僵尸报价（长期不动价） | 降权保留 |

设计上的两个取舍：

- **量纲错误修复而不是剔除。** 单位填错是数据录入问题，不是恶意行为。把价格 ×1000 后落回品种合理区间的，
  修复后正常参与指数，并打上 F012 标记备查。全量 demo 中每次能救回约 3000 条报价。
- **库存非法不牵连价格。** 库存和价格是两个独立的可信度问题，库存填成负数不代表这家的报价也不可信。

## 抗捣乱机制

清洗层管"单条数据是否合法"，可信度层管"这个商家整体是否可信"。

**商家可信度评分**（0~1，point-in-time，只用评分时点之前的历史）：

| 指标 | 识别什么 | 权重 |
| --- | --- | --- |
| `price_bias` 长期相对单元中枢的价格偏离 | 恶意压价/抬价。偏离 15% 以上的挂牌价在钢材现货里没有商业解释 | 主指标，重罚 |
| `vol_ratio` 自身波动 / 市场波动 | 乱跳价 | 主指标，重罚 |
| `spam_days` 灌水天数 | 机器刷量 | 出现即重罚 |
| `outlier_rate` 历史被剔除比例 | 辅助信号 | 轻罚（激进低价策略也会高，不等于恶意） |
| `stale_ratio` 僵尸报价比例 | 挂着不维护 | 轻罚 |

分数低于阈值的商家从该评分生效日起不参与指数，但**不追溯修改历史指数**。

**同源小号识别**：报价长期分毫不差的商家会被归为同一控制人的账号群，可信度打折并按组规模摊薄权重，
等效于把一组小号合并成一个样本。真实独立商家极少长期报价完全一致，所以这个信号的误判率很低。

**权重封顶**：单商家在任一价格单元内的规模权重份额上限默认 10%，超出部分按比例回流给其他商家。
即使某商家挂出天量库存，它对指数的影响也被限制住。

这里有一个容易踩的坑：封顶必须只作用于**规模权重**，然后再叠加信誉与僵尸折减。
如果先折减再封顶，回流会把质量差商家的权重重新抬回来，前面的降权就白做了。

## 指数方法论要点

完整推导见 [`docs/METHODOLOGY.md`](docs/METHODOLOGY.md)，核心是三点：

**1. 不能用"今日加权均价 / 昨日加权均价"当指数。** 商家每天在变、SKU 每天在变、清洗剔除的样本每天也在变。
样本一换均价就跳，跳出来的幅度叠加在真实涨跌上，指数就没有意义了。
正确做法是逐个可比样本算价比再加权聚合（匹配样本链式指数）。

**2. 当日没更新的挂牌价，不能当成"今天没涨没跌"。** 沿用昨日价格会系统性钝化指数——
商家报价越不勤，指数越迟钝，甚至会出现已退出市场的商家还在压低指数。
本算法采用**单元相对插补**：当日未更新的资源按同单元平均变动推算，下次真实报价时再比出相对市场的超额变动。
这样累计涨跌无偏，且只用当期信息，指数可以当日发布、无需事后修订。

**3. 两阶段加权聚合。**

```
单元环比  L_c(t) = exp( Σ w_i · ln(p_i,t / p̃_i,t-1) / Σ w_i )      加权 Jevons
品种环比  L_v(t) = Σ W_c · L_c(t) / Σ W_c                          库存加权 Laspeyres
综合环比  L(t)   = Σ W_v · L_v(t) / Σ W_v                          品种权重加权
指数      I(t)   = I(t-1) · L(t)，  I(基期) = 100
```

权重按月刷新且用上一期的结构（point-in-time），期间靠链式相乘衔接，
既跟得上市场结构变化，又不会在换权日出现台阶。

## 算法有效性验证

`simulate.py` 构造一个**已知真实价格路径**的合成市场，再按现实中常见的方式往里掺垃圾数据
（量纲填错、恶意压价、乱跳价、僵尸报价、小号刷票、机器灌水、字段非法），
然后检验算出来的指数能否还原真值。这是本算法的回归基线，也是调参依据。

180 个交易日 / 120 家商家 / 6 个品种 / 约 14 万条原始记录（其中 15% 的商家在捣乱）：

| 指标 | 干净数据 | 含捣乱数据 |
| --- | --- | --- |
| 指数水平相关系数 | 0.9998 | 0.9959 |
| 日涨跌相关系数 | 0.9989 | 0.9926 |
| 平均绝对误差（相对真值） | 0.125% | 0.569% |
| 捣乱商家召回率 | — | 100% |
| 正常商家误伤率 | — | 0% |

含捣乱数据时整体剔除率约 62%，看着高，但其中绝大部分是模拟的机器灌水记录
（几家商家在部分日子一次性挂出几百条杂乱资源）。真实数据的剔除率取决于数据源质量，
应当逐日盯 `diagnostics` 里的 `reject_rate`：突然升高通常意味着上游采集出了问题。

复现：

```bash
python -m steel_index demo --weight-mode fixed          # 含捣乱数据
python -m steel_index demo --weight-mode fixed --clean   # 干净数据基线
```

测试套件（107 项）覆盖逐条清洗规则、指数数学、以及三类关键性质：

- **样本进出不变性** —— 中途进场/退出一批价格水平明显不同的商家，指数偏移必须 < 0.05 点
- **抗操纵** —— 一家挂 500 倍库存并把价格砸到 -30%，指数偏移必须 < 0.5 点
- **防护有效性对照** —— 关掉封顶与稳健离群剔除后，同一次攻击造成的偏移要大 5 倍以上
  （证明防护真的在起作用，而不是攻击本身没威胁）

```bash
python -m pytest tests -q
```

## 参数调优

所有阈值集中在 `steel_index/config.py`，配置对象不可变，便于复现历史指数：

```python
from dataclasses import replace
from steel_index import SteelIndexConfig, run_index

cfg = SteelIndexConfig()
cfg = cfg.with_overrides(
    cleaning=replace(cfg.cleaning, robust_z_threshold=4.0),   # 极端行情期放宽离群判定
    index=replace(cfg.index, base_date="2025-01-02",
                  category_weight_mode="fixed"),
)
out = run_index(df, config=cfg)
```

常用参数：

| 参数 | 默认 | 什么时候调 |
| --- | --- | --- |
| `cleaning.robust_z_threshold` | 3.5 | 极端行情（如限产、暴涨暴跌）期间价格离散度变大，可放宽到 4~5 |
| `cleaning.carry_forward_days` | 5 | 报价更新频率低的市场可放宽 |
| `cleaning.blacklist_threshold` | 0.35 | 想更保守（少拉黑）就调低 |
| `index.category_weight_mode` | hybrid | `fixed` 用行业消费结构，跨平台可比性最好；`market_value` 完全反映本平台资源结构 |
| `index.min_skus_per_cell` | 3.0 | 样本稀疏时降低，会得到更细的单元划分但噪声更大 |
| `index.include_stale_in_link` | True | 样本里挂着大量长期不维护的报价、指数被拖钝时改为 False |
| `weight.max_merchant_share` | 0.10 | 商家数少时可适当放宽，否则封顶会把权重差异抹平 |

## 模块结构

```
steel_index/
  config.py       品种字典、价格硬边界、全部阈值
  schema.py       列名归一、品种归一、规格分档
  utils.py        稳健统计（MAD、Tukey biweight、加权分位数、权重封顶）
  cleaning.py     五层清洗流水线
  credibility.py  商家可信度评分、同源小号识别
  weights.py      库存加权 + 信誉加权 + 规模封顶
  core.py         指数数学核心（面板、环比、插补、链式）
  index.py        自适应价格单元、品种指数、综合指数、贡献度分解
  pipeline.py     端到端流水线
  diagnostics.py  逐日质量诊断
  simulate.py     含真值的合成数据生成器
  cli.py          命令行入口
```
